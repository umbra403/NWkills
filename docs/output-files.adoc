= The output files
:toc:

For a capture `capture.pcapng` the command line writes four files next to it. The window shows the same tables and writes
them only when you export.

* `capture_kills.csv`: one row per death or kill
* `capture_kills_players.csv`: totals per player, plus per-round columns
* `capture_rounds.csv`: the detected rounds
* `capture_flagbearers.csv`: who spawned carrying a flag, per round

== Kills file
Columns: `round, round_kind, time_s, mm:ss, killer, victim, weapon, teamkill, death_type, respawn_s, review, killer_slot, victim_slot`

`time_s`:: Seconds since capture start (video time = `time_s` + your capture/recording offset).
`weapon`:: One of: firearm: musket/rifle; firearm: pistol; melee: bayonet/spear; melee: sword/sabre; melee: couched lance
(cavalry); cavalry: horse charge (rider hit); melee: hammer/mallet; melee: mace/club?; fists (punch); artillery: cannonball /
shrapnel/canister / explosion; drowning; headshot. See <<weapons>>.
`teamkill`:: `yes` when killer and victim were on the same team. See link:how-it-works.adoc#teams[how teams are decided].
`death_type`:: See <<death-types>>.
`respawn_s`:: Seconds until that victim gets a new agent (normally about 11 s; blank = none within 2 minutes, for example a
player who left).
`review`:: Flags to check, see <<review-flags>>.
`killer_slot`, `victim_slot`:: The player slots the names were looked up from.

[[weapons]]
=== Weapon labels
`headshot` is also what weapon code 0 shows, which includes players leaving the server (see the `world` death type).
Confirmed against video:

* horse charge (class 3: white horse with an orange burst). The killer agent is the horse, so the killer is the rider; see
  link:how-it-works.adoc#horses[horse charges];
* hammer/mallet (class 19: handle with a square head);
* couched lance (class 1: horse and rider icon);
* fists (class 2: fist-with-burst icon; a killer-less version is shown when killer = victim);
* drowning (class 23: killer = victim, score -1);
* cannonball (black ball icon) and shrapnel/canister (spray of small balls).

`mace/club?` (class 16) is a single sighting. Labels with an `(ico_...)` suffix come from the game's icon table only (the art
has not been seen on video) and carry the `weapon?` flag. Class 24 (`special: custom icon 5`) is a volley whose icon nobody has identified yet.

The game picks the killfeed icon with a jump table on the 5-bit weapon class: 0 headshot, 1 couched lance, 2 punch,
3 horse impact, 4 bow, 5 crossbow (the module draws muskets with it), 6 thrown axe, 7 thrown knife, 8 javelin, 9 thrown stone,
10 pistol, 11 musket, 12 one-handed sword, 13 two-handed sword, 14 one-handed axe, 15 two-handed axe, 16 blunt (mace/club),
17 spear (bayonet), 18 morningstar, 19 maul (hammer), 20-26 custom icons 1-7 (20 cannonball, 21 canister, 22 explosion, 23 drowning).
Values above 26 draw no icon.

[[death-types]]
=== Death types
[cols="1,3",options="header"]
|===
| `death_type` | Meaning
| `kill` | Normal blow kill.
| `no-blow death (mount?, not counted)` | Known killer but no blow data and no killfeed line (seen on video: horse deaths). Not counted in any total.
| `horse death (player-owned mount)` | The victim agent is a player's horse. Not a player death; not counted in any total.
| `AI/horse death` | The victim is a bot or unowned mount. Not a player death; counted as the killer's `ai_kills`.
| `world (team swap / left server)` | Killer-less death with weapon code 0 (shown as `headshot`). Confirmed for your own team swap; a player leaving the server looks the same, hence the clusters at the end of events. Your own disconnect death is not in the capture.
| `self-inflicted: fall` | Killer = victim with weapon class 0. Score -1.
| `self-inflicted: drowning` | Killer = victim with weapon class 23. Score -1.
| `self-inflicted: suicide (no admin line)` | Killer = victim with weapon class 2 (fist icon). Admin slays use the same packets and icon and are told apart only by the server's `Slayed Player` line, so this label means no such line was seen. Score -1 (counted as a teamkill).
| `admin slay` | The victim was slayed by an admin (`X Slayed Player Y.`).
| `admin: slayed everyone` | `X Slayed Everyone.`: every self-death or killer-less death at that moment.
| `admin: swapped everyone to spectators` | `X Swapped Everyone to Spectators`: the killer-less deaths at that moment.
| `non-blow death (leave/class change?)` | A death message without a blow and with no known killer.
|===

The three admin types are read from the server's text lines; those rows stay in the file but are not counted as kills,
deaths or teamkills. Other admin lines (bans, beacons) are not used. The exact causes inside the last few non-admin types
are still provisional.

[[review-flags]]
=== Review flags
* `killer?` / `victim?`: the player could not be resolved.
* `before-sync`: the name is unresolved in the first ~90 seconds of the capture.
* `name-from-later-data(killer|victim)`: the name was filled in from later sightings of the same agent in this capture.
  `name-from-later-data(killer-from-score)` means the killer of a horse charge was taken from the score change.
* `weapon?`: unknown weapon class, shown as `class N`.
* `self`: self-inflicted death.
* `teamkill?(score disagrees)`: the teams say one thing and the killer's score change the other (rare).
* `teamkill?(burst)`: several kills by one player shared one scoreboard change. The number of teamkills among them is exact, which of them were teamkills is a guess (victims with the killer's regiment prefix first).
* `runaway-horse`: a horse charge nobody rode and no score claims.

`(AI)` in a name column is a bot, `(world)` means no killer.

== Players file
`kills` = kills minus teamkills over all non-warm-up rounds, like the scoreboard. `deaths` and `teamkills` cover the same
rounds. `ai_kills` is bot kills.

`score_at_capture_start`, `score_at_capture_end`:: Scoreboard values the server sends when you join and on every change.
`score_gap`:: The scoreboard change minus what was recorded as kills and teamkills. 0 means nothing was missed; positive
means score we did not see as kills (for example kills before you joined). Remaining gaps are normally 0 to +-2.
Per round, four columns `R<n>(<kind>)_kills|_deaths|_teamkills|_score_gap`:: Per-round `kills` do *not* subtract
teamkills (plain counts). Warm-up rounds keep their columns but are left out of the overall totals.

Not counted in the totals: horse deaths, `no-blow death` rows, deaths of `(AI)` victims (those go to the killer's `ai_kills`),
and admin deaths. A team swap (a killer-less death after which the player respawns) costs the player 1 point and is counted
as such in `score_gap`, but is not a kill or a death. Leaving the server costs nothing.

How the scores are read is described in link:how-it-works.adoc#scores[Scores].

== Rounds file
Columns: `round, start_s, end_s, length_s, started_by, tickets_zero_at_s, tickets_zero_team, kills_after_tickets_zero, kind, death_msgs, method, review`

`death_msgs`:: The number of rows in the kills file for that round (one per death, copies removed). It is not the raw message
count: the server sends every death once per recipient, and each recording catches a different number of those copies.
`kind`:: `pre-live` (from capture start until the first detected start), `warm-up` (not live; excluded from the totals) or `live`.

How round starts are found is described in link:how-it-works.adoc#rounds[Rounds].

== Flagbearers file
Columns: `round, round_kind, player, player_slot, class, flag, spawns, first_spawn_s, first_spawn_mm:ss, last_spawn_s, review`

One row per player, round, class and flag. The class comes from the spawn message's troop id and the module's `troops.txt`
(troop index = field minus 1); the flag comes from `item_kinds1.txt`. Both tables are bundled (`data/flag_troops_nw.json`,
`data/flag_troops_nwe.json`).

NW:: A spawn counts when the class can carry a flag (NCO classes, French `colours` classes) *and* a flag item of that class is
in the spawned loadout.
NWE:: It has dedicated `*_flag_bearer` classes; every spawn of one counts. `flag` is filled in when the loadout shows the flag
item, otherwise `unknown` (about 40% of NWE rows on the Tuesday capture).

The server type is chosen from the largest loadout item id in the capture (above 1023 means NWE); another module needs its
own two table files. Loadout item ids are trusted only for the flag itself, and only together with the class: the servers'
item tables differ from the module files for armour, so armour and other items are not decoded.

Misses: your own respawns (no spawn message, only a type-18 update) and agents already on the map when you connected. On the
two NWEVENT captures (two viewpoints of one event) 23 of 28 (player, flag) pairs were identical; the rest were roster-slot
differences. `review = name?` means the player's name could not be resolved.
